先说结论

这个项目不是一个“输入故事后全自动出成片”的黑箱。它更像一条带 AI 助手的制作流水线：AI 负责写结构、拆资产、拆分镜和写提示词；图片模型负责做参考图；视频模型按每条分镜单独出片；最后 FFmpeg 把现有片段按顺序硬切拼起来。

代码自动执行 AI 按提示词判断 创作者需要检查 当前没有实现

真正自动串起来的部分

保存数据、调用 Agent、资产去重、保存提示词、提交生图/视频任务、轮询结果、下载到本地、回填数据库、顺序拼接。

仍然依赖 AI 自觉的部分

改写是否忠实、角色有没有漏、道具是否真关键、分镜节奏是否合理、提示词是否遵守每条细则。这些规则写进了 Prompt，但不是程序算法逐条验收。

最重要的现实：最终导出只是把已有分镜视频按镜号顺序拼接。没有自动转场、没有字幕烧录、没有 BGM/音效混音，也没有统一画幅、帧率和音轨的预处理。

完整流程图

1新建项目填写标题，选择全局视觉风格和画幅。
2新建剧集填写可选标题，锁定 480p 或 720p 等输出分辨率。
3粘贴原文手动输入或粘贴小说/故事。当前界面没有已证实的剧本文件导入。
4AI 优化剧本把叙述改成带场景头、动作和对白的格式化剧本；也可跳过，直接把原文当剧本。
5提取资产分别提取角色、场景、关键道具，与项目已有资产去重并关联到当前集。
6资产定妆为角色、场景、道具生成最终生图 Prompt，再出参考图或上传自己的图。
7拆分镜段落每条数据库分镜代表一次视频生成，内部可包含 2-4 个子镜头。
8生成视频提示词按 3 秒时间线写动作、机位、氛围和台词，并用 @名字绑定参考素材。
9逐镜生成视频前端组装参考图和 Prompt，后端调用视频供应商，完成后下载到本地。
10导出整集选择已有视频的分镜，FFmpeg 按镜号硬切拼接并输出 MP4。

白话类比：格式化剧本是“拍什么故事”；角色/场景/道具图是“美术设定”；分镜段落是“一次让视频模型生成的 8-15 秒小片”；视频 Prompt 是“这小片每 3 秒怎么演”；最终导出是“把这些小片首尾接起来”。

1. 新建项目和剧集

新建项目时真正保存什么

  • 项目标题：必填。
  • 视觉风格：保存的是一个风格键，例如 anime、3d。真正的英文风格 Prompt 会在后面生图、生视频时再读取。
  • 画幅：16:9、9:16、1:1 或 adaptive。

新建剧集时真正保存什么

剧集保存原始内容、格式化剧本、图像/视频模型配置、分辨率和最终成片地址。常规界面中，剧集创建时选 480p 或 720p；分镜视频任务会优先使用剧集锁定的分辨率。

注意：项目阶段只选择“视觉长什么样”，不会因此改变剧情改写方法、人物提取规则或分镜节奏。

2. 手动输入脚本后，AI 优化具体怎么做

  1. 你把小说、故事梗概或原始脚本粘贴到“原始内容”区，前端先保存到 episodes.content。
  2. 点击“AI 改写”，前端调用 script_rewriter，只发一句功能指令：“请读取剧本并改写为格式化剧本，然后保存”。
  3. Agent 自己调用工具，从数据库读取原文。
  4. 文本模型根据系统 Prompt 和编剧 Skill 生成格式化剧本。
  5. Agent 必须再调用保存工具，把完整结果写进 episodes.script_content。

“优化”并不是润色几个词，而是换成可制作结构

原文可能是AI 被要求改成
“她很紧张，担心对方发现秘密。”可见动作，例如攥紧包带、避开目光；必要时用对白或画外音。
一大段叙事按地点和时间拆成连续场景，场景号为 S01、S02……
对话混在叙述中角色名：（状态/表情）台词内容
没有制作格式## S01 | 内景 · 咖啡厅 | 黄昏

它被要求保留主线和角色关系、增强画面感、更多用对白推进、每场戏约 30-60 秒，并且此时禁止写景别、角度、推拉摇移，因为镜头语言留到后面的分镜阶段。

改写幅度：Skill 建议成稿只比原文增加约 20%-30%，主要增加场景头、动作和对白格式，不是让模型随意扩写剧情。

你要检查：人物关系、关键反转、原台词含义、场景先后。Prompt 说“保留主线”，但模型输出仍有随机性，程序不会逐句比对原文。

一个真实的保存竞态：前端点击 AI 改写时会先发起保存原文，再立即发起 Agent 请求，但代码没有等待保存请求完成。多数时候保存会先到达；如果你刚改完大段内容就马上点改写，理论上 Agent 可能读到上一次保存的版本。稳妥做法是先单独保存，确认后再点 AI 改写。

跳过改写：点击“跳过”时，代码只是把原始内容原样复制到 script_content。后续仍可继续，但资产提取和分镜质量更依赖你原文本身是否结构清楚。

3. 角色、场景、道具是怎么拆出来的

界面可单独提取角色、场景、道具，也可连续提取。三次任务都使用同一个 extractor Agent，但每次动态指令会明确限制“本次只提取某一类”。它优先读格式化剧本；没有格式化剧本时才退回原文。

角色：谁需要固定长相

  • 不能漏掉有台词或重要动作的人。
  • 主要保存：名字、主角/配角/龙套定位、样貌、妆造；背景和关系可选。
  • 样貌包括年龄感、五官、体态、外在气质；“冷峻”要改写成“眼神冷、表情克制”这种看得见的特征。
  • 妆造包括发型、服装、妆面、配饰。

场景：在哪里、什么时候

  • 以“地点 + 时间段”为唯一组合。相同咖啡厅的白天和深夜，会被视为两个场景。
  • 场景描述保存空间、陈设、年代质感、关键视觉元素。
  • 光影单独保存光源、色调、明暗和氛围。
  • 它是背景资产，后续场景参考图被强制要求完全无人。

道具：不是画面里出现的每件东西

代码中的 Prompt 对道具非常克制：一集通常只提 0-3 个。一个东西要同时满足“直接推动剧情”和“值得单独生成参考图”。

应提取

凶器、信物、关键合同、证据、会被交接/损坏/发现并导致转折的物品。

通常不提取

普通手机、水杯、筷子、香烟、桌椅、灯具、门窗、挂画，以及只出现一次但不影响剧情的物品。

怎样避免重复资产

  • 角色和道具：去掉括号内定位、去空格、转小写后做精确比较。例如“林小雨（主角）”和“林小雨”会复用已有资产。
  • 场景：规范化地点，再加时间段做精确比较。
  • 命中已有资产时复用原 ID，并把它关联到当前集；不是每集都重新造一套角色。
边界：所谓“智能提取”是 LLM 按规则输出结构化字段，代码负责去重和落库。程序本身没有一套自然语言解析算法来证明 AI 一定提全。

4. 角色、场景、道具参考图怎么生成

资产有两条路：让系统生图，或者你手动上传。正常生图不是直接把提取结果扔给图片模型，而是先让 prompt_generator 再写一版“最终生图 Prompt”。

最终 Prompt 的组装公式

项目风格英文 Prompt + “, ” + 资产专用 Prompt

例：日漫赛璐璐风格词
  + 角色四视图规范、该角色样貌、服装、白底、均匀光、禁止文字和道具
  = 真正交给图片模型的 final_prompt

角色参考图

一张人物设定表：左侧正脸近景；右侧同一角色正面全身、90°侧面、背面。要求等高对齐、A 字自然站姿、白底、柔和均匀光、同脸同发同服，不要动态姿势、道具、他人、标签或水印。

场景参考图

稳定机位的广角空镜。明确前景/中景/背景、入口、地面、墙面和 2-4 件主要陈设的相对位置。绝对不能出现人，包括背影、剪影、倒影和照片里的人。

道具参考图

纯白底单品产品图，只出现这个物件，完整不裁边，比例准确。通常 3/4 微俯视；平面物用俯拍。不要手、人物、场景、叙事背景、文字、水印。

失败时的兜底

如果 Agent 没写出最终 Prompt，路由会拼一个更简单的英文兜底 Prompt。它仍会加入项目风格词，并保留角色设定表、场景无人、道具白底等基本限制。

生图任务实际发生什么

  1. 创建一条 sys_task，状态为 processing。
  2. 按已配置的图片供应商组装请求。OpenAI 有参考图时走图片编辑；Gemini 把参考图内联；火山图片适配器目前不使用参考图字段。
  3. 同步返回就立即处理；异步返回则后端轮询。
  4. 成功图片下载到本地 data/static/images，生成缩略图，并把本地地址写回角色/场景/道具。

参考图限制：图片生成用的参考图会去重、压缩到最长边 768 像素左右，最多 6 张；压缩失败的参考图会被跳过。

5. 镜头是怎么提出来的

这里最容易误解：“一条分镜”不是传统意义的一次单镜头，而是一次视频模型生成任务。它叫“分镜段落”，长度 8-15 秒，内部允许有 2-4 个子镜头。

AI 的拆分顺序

  1. 读取格式化剧本，以及当前集关联的角色、场景、道具和已有分镜。
  2. 先找叙事节拍：开场、触发、规则揭示、情绪爆发、反转、收尾等。节拍边界强制另起一段。
  3. 每段保持在同一场景内；内部可以换景别、角度和拍摄对象。
  4. 为每段绑定场景 ID、角色 ID、关键道具 ID，并写画面描述、氛围、时长和视频 Prompt。
  5. 第一批最多保存 8 段，并清掉整集旧分镜；后续批次继续追加。

总时长和分镜数量怎样估算

目标总时长（分钟）≈ 格式化剧本字数 ÷ 500
分镜段落数量 ≈ 目标总秒数 ÷ 12
允许总数上下浮动约 20%

过渡段：8-10 秒
普通叙事：10-15 秒
爆点/反转/情绪爆发：12-15 秒
有台词时的最低时长 = 台词与旁白字数 ÷ 4.5 + 2 秒表演余量

一条分镜里保存什么

description 按 【镜头1】、【镜头2】 写观众真正看见的动作、表情、肢体和听见的台词；atmosphere 写光线、色调和环境感受；另有场景/角色/道具绑定、时长、视频 Prompt 等。

重拆分风险：默认重新拆整集时，第一次保存会真实删除旧分镜和旧绑定。如果模型在后续批次中途停止，数据库可能只剩不完整的新分镜。重拆前最好确认旧结果是否还需要。

6. 视频提示词是怎么组织的

分镜 Agent 会尝试在拆分时直接生成 video_prompt。如果某些分镜没有 Prompt，或你点击批量/单条生成，系统会再调用 prompt_generator 补写或覆盖。

被要求的标准格式

出场人物：@小明、@小红；场景：@咖啡厅；道具：@红色信封。
0-3秒：@咖啡厅，近景固定镜头，@小明低头捏紧@红色信封，暖黄侧光……
3-6秒：切到门口全景，@小红推门进入，停顿后望向@小明……
6-9秒：切回中景，@小明抬头说：「你终于来了。」……
  • 第一行列出出场人物、场景和关键道具。
  • 后面按连续 3 秒一行。
  • 每个 【镜头N】 对应 1-2 行时间段，顺序一致，不漏、不新增子镜头。
  • 每行写“谁 + 可见动作 + 景别/角度/运动 + 氛围”；情绪必须变成表情和动作。
  • 台词只能来自分镜 description，不能临时编新台词。
  • 角色、场景、道具必须写精确的 @名字，便于后续挂参考图。

“按模型特性优化”的真实程度：动态消息会告诉文本 Agent 视频配置的显示名称和 provider，但没有把完整模型能力表传进去。具体怎样适配更多是文本模型自行理解；真正硬性的时长、分辨率和素材数量限制，是后面的供应商适配器再校验。

7. 每条分镜视频怎么生成

前端先做一次很关键的“接线”

后端不会因为收到了分镜 ID，就自动去数据库找角色和参考图。正常界面会在浏览器里完成这一步：

  1. 按固定顺序收集已绑定且已有图片的资产：场景 → 角色 → 道具。
  2. 去重，并按当前视频供应商允许的数量截断。
  3. 把 Prompt 里的 @小明 改成 @图片2小明 这类编号。编号与参考图数组的位置一致。
  4. 向后端发送：分镜 ID、视频 Prompt、时长、项目画幅、剧集分辨率、模型配置、参考图 URL，并默认请求生成音频。

例子：如果参考图顺序是“咖啡厅、林小雨、旧怀表”，Prompt 就会相应写成 @图片1咖啡厅、@图片2林小雨、@图片3旧怀表。这不是 AI 自己猜图，而是前端按绑定关系机械编号。

后端和视频模型之间

  1. 后端在视频 Prompt 最前面再次加入项目视觉风格英文词。
  2. 创建视频任务，并根据供应商转换字段、时长、画幅、分辨率和参考素材格式。
  3. 供应商异步生成时，后端每 10 秒查询一次，最多 300 次。
  4. 成功后下载到 data/static/videos，尝试截取海报帧，把本地路径写回 storyboards.video_url。
视频供应商素材与时长分辨率/音频的实际处理
火山 Seedance 2文本 + 参考图/视频/音频；4-15 秒。仅 480p/720p，1080p 会降到 720p；把 generate_audio 继续传给上游。
MiniMax H3支持首尾帧、参考图/视频/音频；4-15 秒。480p/720p 变 768P，1080p 变 2K；忽略 generate_audio，因为适配器认为 H3 原生音画同步。
阿里云 Wan 3.0支持首尾帧、参考图/视频/音频、文件和网页链接；2-30 秒或 -1。支持 480P/720P/1080P；继续传音频、Prompt 扩写、水印、种子等参数。
音频不是统一保证：界面默认发 generate_audio: true，但不同模型处理不同，合并阶段不会补配音、补音轨或修音。因此“勾了生成音频”不等于每个片段一定有可用对白和声音。

8. 最后怎么合成视频

  1. 导出页让你勾选已经有视频的分镜。
  2. 后端仍按 storyboard_number 从小到大排序，不按你点击的先后顺序。
  3. 没生成视频的分镜会被直接跳过，所以“选了分镜”不代表它一定进成片。
  4. FFmpeg 用 concat 列表首尾连接片段，将视频重新编码为 H.264、音频重新编码为 AAC 48kHz/192kbps。
  5. 输出为 data/static/merged/<uuid>.mp4，探测实际时长、生成封面，并写回当前剧集。
实际合成效果：片段 1 → 硬切 → 片段 2 → 硬切 → 片段 3

视频：H.264 / preset medium / CRF 23
音频：AAC / 48 kHz / 192 kbps
网页播放优化：+faststart
已有没有实现
按镜号排序、选择性拼接、视频和音频重编码、成片封面、下载。淡入淡出、转场、镜头时长拉齐、字幕烧录、BGM 生成与混音、音效混音、旁白轨合成。
片段有原生音频时，音频会一起进入 AAC 编码。缺音轨补静音、音量统一、响度标准化、画幅/帧率/音轨布局统一的前置处理。

数据库虽然有 bgm_prompt、sound_effect、subtitle_url 等字段，但当前这条合成代码没有使用它们。

不同风格在每个阶段分别做什么

代码里不是“每种风格都有一套编剧 Prompt + 提取 Prompt + 分镜 Prompt”。实际只有一条全局英文风格前缀，机械地加到角色图、场景图、道具图和视频生成 Prompt 前面。

阶段风格是否参与具体做法
AI 优化剧本不参与所有风格共用同一套编剧 Prompt。
角色/场景/道具提取不参与提取的是叙事和资产字段，不读项目风格。
分镜叙事拆分不直接参与节拍、时长和绑定规则一致。
角色最终生图 Prompt自动前缀风格词 + 人设四视图规范。
场景最终生图 Prompt自动前缀风格词 + 固定机位无人空镜规范。
道具最终生图 Prompt自动前缀风格词 + 白底产品图规范。可能与某些“电影感”风格词发生语义拉扯。
视频生成自动前缀提交视频任务时，后端把同一个风格词加到视频 Prompt 最前面。
最终合成不参与FFmpeg 只拼文件，不再做调色或风格统一。

整个流程到底用了哪些提示词

运行时不是只读一份 Prompt。每个 Agent 的系统指令由三层拼起来：主 Prompt 文件 + 匹配的 Skill 规则 + 内容语言指令；前端或服务端还会发送一条“这次具体做什么”的动态用户消息。

Prompt 1：剧本改写

角色：专业编剧，把小说改为短剧剧本。

核心要求：读原文 → 自己改写 → 保存完整剧本；保留主线和人物关系；叙述变可见动作；对白推动；每场 30-60 秒；禁止镜头语言；约 20%-30% 格式化增量；心理变动作/表情/旁白；场景号连续。

动态消息原文：请读取剧本并改写为格式化剧本，然后保存

语言和模型也会改变结果

  • 内容语言支持中、英、日、韩。非中文时优先读取对应语言版本的 Prompt/Skill，并追加最高优先级语言指令。

最容易误解的 10 件事

  1. 不是全自动成片：几个阶段需要你主动点击，流程导航也只是界面状态，不是严格的后台状态机。
  2. 风格不改故事：风格只进入图片和视频生成，不参与剧本优化、资产含义或叙事拆镜。
  3. 一条分镜不是一个单镜头：它是一段视频任务，里面允许 2-4 次切镜。
  4. 后端不会自动找参考图：正常 UI 在提交前按绑定关系组装；其他客户端若直接调 API，要自己传参考图。
  5. 不是每条分镜都有分镜图：当前主流程直接用角色/场景/道具参考图生成视频，数据库虽留有首帧/尾帧/合成图字段，但不是必经步骤。
  6. 道具不是越多越好：规则明确要求通常 0-3 个剧情关键道具。
  7. “生成音频”不是配音系统：它只是把开关交给支持的视频模型，项目没有独立 TTS、对白对齐和后期混音链路。
  8. 最终时长不等于分镜时长相加：视频供应商可能返回不同时长，合成使用源视频的真实时间戳。
  9. 服务重启可能留下 processing：生成轮询是进程内异步任务，没有看到启动后自动恢复旧任务的逻辑。
  10. Prompt 是约束，不是验收器：AI 仍可能漏角色、写错绑定、超出剧情；代码只验证部分 ID、数量和格式。

作为创作者，最稳的实际操作顺序

  • ① 原文先按事件顺序写清楚，人物名字保持统一，不要一会儿全名一会儿昵称。
  • ② AI 改写后先校对故事和对白，再进入资产提取；不要指望分镜阶段替你修剧情。
  • ③ 角色资产重点校对年龄感、发型、服装和辨识特征；这些会反复成为参考图。
  • ④ 场景资产确保“地点 + 时间”合理，场景图保持无人，否则视频模型容易把背景人物当主角。
  • ⑤ 道具只保留会特写或影响剧情的物件。普通物品放进场景/视频 Prompt 即可。
  • ⑥ 先生成并挑好资产图，再拆分镜。参考图质量往往比多写几个形容词更影响角色一致性。
  • ⑦ 分镜生成后逐条看四件事：有没有跨场景、台词能否在时长内说完、绑定是否正确、动作是否能在 8-15 秒完成。
  • ⑧ 视频 Prompt 里的 @名字必须与资产名完全一致；改名后要重新检查。
  • ⑨ 先单独试生成一条复杂分镜，确认当前视频模型对多人、对白和参考图的能力，再批量生成。
  • ⑩ 导出前逐条播放，确认每条都有声音、画幅和清晰度可接受；需要字幕、BGM、音效和转场时，当前版本之后仍要进入剪辑软件。
